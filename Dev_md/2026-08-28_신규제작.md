  ④⑤는 "다음 단계" 안내 카드만 두고 로직은 만들지 않았다(아래 판단 근거 참고).

- `css/style.css`: CLAUDE.md §9.1(컨테이너 3단)·§9.7(반응형 그리드 minmax(0,1fr))
  기준으로 새로 작성.

## ④⑤을 다음 단계로 넘긴 이유

이메일 원문에 "1대분 최종 MH"를 대표사양 조합과 BOM MH로 **어떤 공식으로** 합산하는지
(단순 합산인지, 옵션별 가중인지, 기준 대표사양 대비 차분인지)가 명시돼 있지 않았다.
지어내서 다섯 탭을 다 채우면 계산이 틀렸을 때 아무도 모른다 — ①~③처럼 사양서에서
확인 가능한 것만 만들고, ④⑤는 화면에 "다음 단계"로 명시해 대표님이 제출자에게
공식을 확인한 뒤 이어서 구현하도록 남겼다.

## 검증 (단순 통과 확인이 아니라 손계산 대조)

`test/logic.test.js` 8개 전부 통과 외에, 브라우저에서 실제 업로드→계산까지 돌려
샘플 데이터 기준으로 **손으로 계산한 값과 화면 출력이 일치하는지** 대조했다.

- ASSY-FRAME-01: Old MH = 0.62(SMP-1001×2)+1.10(SMP-1002×4)+1.20(SMP-1003×1) = 2.92,
  New MH = 0.90(SMP-1001×3)+1.10(SMP-1002×4, SMP-1003 삭제) = 2.00, ΔMH = -0.92
  → 화면 출력과 정확히 일치.
- ASSY-PIPING-01: Old MH = 1.20+0.55 = 1.75, New MH = 2.10+0.55+0.35(SMP-1001 신규편입) = 3.00,
  ΔMH = +1.25 → 화면 출력과 정확히 일치.
- 대표사양: DX80R이 Old(BCC 대표)→New(DSC 대표)로 바뀐 것을 `changed:true`로,
  EX10이 대표사양 미선정→선정으로 바뀐 것도 `changed:true`로 정확히 잡음.
